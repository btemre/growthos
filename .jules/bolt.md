## 2025-02-18 - Server-side Subscription Filtering with Client-side Sorting
**Learning:** Subscribing to an entire user or admin's collection (e.g., all tasks) and filtering them on the client-side for details views is extremely inefficient. It leads to huge data transfers, high client memory churn, and heavy CPU usage during lists updates. However, querying on multiple fields with server-side sorting in Firestore normally requires complex custom composite indexes. By combining a server-side equality query (`where`) with client-side sorting on `createdAt`, we get the best of both worlds: highly filtered payload size and zero index configuration overhead.
**Action:** Always prefer server-side equality filters combined with client-side array sorting for detail/related lists inside detail views.
